# ADR 0008 Agent 运行时与模型网关的设计

状态：已采纳（J3，2026-10-16）。

## 背景

主提示词第 8 节要求自研一个轻量的 Agent 循环，保持源码可读，支持子 Agent、流式输出、人工确认的挂起与恢复；模型调用走一条可配置的处理管道；每一步都有追踪，租户视角看不到标品指令原文。ADR 0006 决定后端用 Java，并以本项目作为 Spring AI 的第一次试验。需要决定 Spring AI 用到哪一层、哪些部分自己写。

## 决策

### Spring AI 用在模型这一层

- 模型提供方都实现为 Spring AI 的 `ChatModel`：Anthropic 和 OpenAI 兼容协议用 Spring AI 的官方模块（`spring-ai-anthropic`、`spring-ai-openai`），脚本化模型是自己实现的 `ChatModel`（`ScriptedChatModel`）。三者走同一条处理管道，追踪和计费口径一致。
- 调用模型用 `ChatClient`，关闭工具调用 Advisor 的自动注册（`AdvisorParams.toolCallingAdvisorAutoRegister(false)`）。Spring AI 2.0 里工具执行已经从 `ChatModel` 移到 `ToolCallingAdvisor`，关掉它之后，模型返回的工具调用原样交给平台运行时，由运行时在执行前做鉴权、守卫和确认。
- 工具只用来向模型声明（名字、说明、入参 schema），对应的 `ToolCallback` 不会被调用。模型要求的工具名只能用字母、数字、下划线和连字符，语义查询工具名里的点在发出前换成下划线，解析响应时再换回来。
- 处理管道里调用模型前后的三个环节是 Spring AI 的 `CallAdvisor`：输出过滤、脱敏与还原、输入过滤，按这个顺序包在模型调用外面。知识检索注入和提示模板在调用 `ChatClient` 之前完成，因为它们决定系统提示词本身。每个环节在追踪里是模型 span 下的一个 pipeline span。
- 模型档位（fast、reasoning、judge）到模型名的映射、提供方选择、Key 都来自环境变量；选了真实提供方却缺 Key 时启动即失败，不会静默退回脚本化模型。

### Agent 循环、技能与工作流自己写

Agent 循环、工具网关、技能执行器、工作流引擎、监督层都在 `eab-runtime` 里自己实现，不用框架的 Agent 抽象。理由是平台的大部分逻辑在工具调用前后：鉴权点 2、3，写级别守卫，确认与挂起，子 Agent 的身份与深度，输出守卫，钩子的失败隔离。这些需要在每一次工具调用上精确控制，自己写的循环一百多行，读起来比在框架的扩展点里拼装更直接。

### 挂起与恢复用运行日志重放

运行需要人工确认时挂起。保存的状态是一份运行日志：按结构化路径（例如 `run/turn:2/tool:call_1`）记录模型调用结果、工具调用结果、鉴权裁决和用户的确认决定，另加脱敏映射。用户确认或拒绝后，运行从头重新执行，日志里已有的步骤直接取记录的结果，不再调用模型、不再重复写入 ERP，运行重放到挂起的位置，再按用户的决定继续。

这样做的好处：

- 不需要序列化 Spring AI 的消息对象和调用栈，状态就是一个 JSON；
- 子 Agent、技能、工作流、钩子里的确认都用同一种方式挂起和恢复；
- spanId 由运行编号和同一条路径派生，重放时得到同一个 spanId。挂起时未结束的 span 以 suspended 状态落库，恢复后被最终状态覆盖，追踪里看到的是一次完整的运行；
- 写操作带由运行编号和路径派生的幂等键，即使重放到写操作之后也不会重复写入。

前提是运行是确定的：同一份日志重放出同样的分支。模型调用、工具调用都被记录，循环里没有其他不确定的输入。

### 剧本格式

脚本化模型读取 `demo/scripts/*.yaml`。剧本按“Agent 加用户话术”匹配，按本轮已经完成的工具调用批次数决定下一步：要么是一批工具调用，要么是最终回复。回复用 mustache 模板基于真实的工具结果渲染，结构化结果和工具参数里以 `=` 开头的值用 CEL 求值，回复模板可以引用结构化结果。这样回复里的单号、天数、金额都来自本次运行的工具结果，输出守卫的核对对脚本化模型同样有效。格式见 `demo/scripts/README.md`。

### 追踪里的系统提示词只按片段保存

模型 span 不保存拼接后的系统提示词原文，只保存片段数组：片段编号、来源、保密标记、文本。读取接口按查看者裁剪，租户视角下保密片段换成占位块（ADR 0004）。OTLP 导出只带片段编号，不带文本。

### 需要审批的写操作先一律拒绝

策略引擎判定为 approve（需要审批）的工具调用，在审批收件箱上线（P8）之前一律拒绝，并在工具结果里说明。失败即拒绝，不降级为确认。

## 影响

- 新增 `eab-tracing`、`eab-runtime` 两个模块；平台新增运行、追踪、记忆、告警、IM 消息的存储（Flyway V2），以及 `/runs`、`/traces`、`/memory`、`/mcp` 等接口；新增 `eab-cli` 模块承载 `pnpm agent:run`。
- 换用真实模型时，只需设置 `EAB_MODEL_PROVIDER` 和对应的 Key，运行时、管道、追踪都不变。
- 运行日志会随运行变长；演示里一次运行最多八轮，日志只有几十 KB。长时间运行的工作流（P4 的事件等待）沿用同一机制，届时再评估日志的清理策略。
