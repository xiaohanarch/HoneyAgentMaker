# ADR 0015 架构视图与演示控制台

状态：已采纳（P10，2026-10-19）。

## 背景

主提示词第 17、18 节要求 P10 把系统整理成可对架构师和管理者讲解、可 15 分钟演示完成的形态：一张五层两翼的架构图，选中一次运行后按时间线高亮经过的组件；Studio 右上角的演示控制台提供重置、跳到各故事起点、触发事件、发布标品新版本、切换用户、集成账号对照、一键生成完成态。DEMO.md 的六个故事各自独立，每个都要从确定起点开始，任何一屏出错都能就地恢复。

## 决策

### 架构图是静态 SVG，组件映射是纯函数

架构视图不引图形库（React Flow 等），组件集合固定为五层两翼的 22 个组件（`components.ts`），Diagram 按 zone 画静态 SVG 网格。span 到组件的映射写成纯函数 `mapSpan(span, run)`，输入一条 span 输出组件 id 集合，每个映射分支有单测。理由：组件不会动态增删，图形库的拖拽、自动布局都用不上；纯函数让"哪个 span 点亮哪些组件"可测试、可审查，e2e 直接断言 `arch-component` 的 data-state。

回放时长归一化为 12 秒（`REPLAY_MS`），与真实耗时无关：演示要的是看清组件依次点亮的节奏，一次几十秒的运行按真实时间回放反而讲不动。速度档位（0.5、1、2 倍）只改推进步长。

### 鉴权点 1 与受托运行做诚实处理，不伪造后端数据

四处鉴权里只有 2 和 3 有独立 span。鉴权点 1（入口校验令牌）没有，回放的第 0 帧在前端合成：点亮统一入口与左翼鉴权，字幕写明这一步没有独立 span。受托运行（业务事件触发）的入口也不在运行内，前端按运行的 mode 合成首步"业务事件"。鉴权点 4 的裁决发生在 BO API 内部，并入 BO 工具的点亮并在图注说明。三条都是前端展示层的合成，不改后端数据、不改追踪结构；数据源只用 `GET /runs` 和 `GET /traces/{traceId}`，两个接口服务端已按查看者裁剪，三层资产可见性（租户看不到标品指令原文）天然保持。

### 演示状态端点的门禁

三个新端点（`POST /demo/v1/reset`、`/demo/v1/story-start`、`/demo/v1/complete`）在 `platform` 的 `console` 包，门禁照抄既有先例：演示模式未开启一律 404（`AssistController` 的 `/demo/v1/events`、`HubController` 的 `/hub/demo/*` 同款），演示状态操作再要求租户管理员（403），按用户每分钟 10 次限流（429）。触发业务事件与模拟升级沿用既有端点，门禁不变。前端不隐藏非管理员入口，只置灰并提示，服务端硬校验为准。

### 重置先 DemoERP 后平台，HTTP 版与 CLI 等价

`ResetDemo` 增加重载 `reset(PlatformServices services)`，用平台自身的连接在单事务里跑与 CLI 完全相同的两张清单（运行期表、要撤回的资产），保证 `pnpm seed:reset` 与控制台重置语义一致。HTTP 重置先调 DemoERP 的内部端点 `POST /demo/v1/reset`（内部调用密钥，与事件触发同一通道）重新生成业务数据，再重置平台；DemoERP 不可达返回 502 且不动平台数据，避免出现 ERP 旧数据配平台新状态。

撤回范围自本阶段起扩大为除基础设施外的全部租户资产（`tenant.%` 减去 `AssetSeeder.TENANT_INFRA`）：启动入库只覆盖连接、工具来源、工作流、远程 Agent 这些基础设施，其余租户资产必然来自演示过程，整组撤回即回到首次启动状态。P9 时逐条点名撤回故事 E 的三份资产（见 0014）的做法，在快照、经验回流、方案卡陆续加入后不再可维护。

### 故事起点与完成态快照

故事 A 到 E 的起点都是纯重置：A 的向导、B 的扩展、C 的远程 Agent（启动资产）、D 的演示委托（重置后 `ensureDemoDefaults` 重建 DLG-0001）都不需要额外状态。故事 F 的升级回归需要故事 B 的扩展已发布，起点在重置之上再发布 `assets/tenants/t001` 完成态快照；发布前先清空该租户已发布资产，快照文件是完成态的唯一权威，演示中途经 Studio 发布的扩展与快照同名工具冲突时组装门禁（TOOL_NAME_CONFLICT）会拒绝重播，先清空再整树重播让重演结果确定。快照必须播整棵 `tenants/t001` 树：只播部分会让评测集因目标缺失发布失败。

一键完成态等于故事 F 起点再加 `HistorySimulator` 生成的 30 天模拟历史，让治理中心与架构视图有趋势数据可看，不进演示主线。

### e2e 的状态纪律

Playwright 按文件名字典序串行执行，`demo-console` 与 `story-f` 两个 spec 都以纯重置收尾，后续 spec（studio）拿到首次启动状态。不新增脚本化模型剧本、不新增脚本文案断言，故事 D、F 的断言全部复用既有剧本，ECS 上真实模型运行不受影响。

## 影响

- DemoERP 新增内部重置端点；平台新增 console 包与三个端点，接口说明见 `docs/studio-api.md` 的"演示控制台"一节。
- `pnpm seed:reset` 与控制台重置共用 `ResetDemo`，改清单时两边同时生效，`DemoConsoleEndToEndTest` 与 CLI 路径都有测试覆盖。
- 架构视图的组件 id（`ux-entry`、`cap-model` 等）被 e2e 断言引用，改名要同步 `mapSpan` 测试。
- 演示讲解词 `demo/DEMO.md` 是演示的操作脚本，界面按钮名、端点、剧本话术改动时要同步更新。
- 阶段验收脚本 `scripts/acceptance-p10.mjs` 只用 HTTP，对运行中的演示环境验证控制台、故事 F 起点、升级回归、完成态与回放数据。
