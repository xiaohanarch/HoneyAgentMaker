# ADR 0013 治理中心、评测引擎、升级回归、方案包与经验回流

状态：已采纳（P8，2026-10-16）。

## 背景

主提示词第 11、12 节和故事 D、F 要求：治理中心能看到全部资产及其血缘、上架准入、三层运行指标、审计反查、委托管理、风险告警；标品升级时用租户扩展的评测集自动回归并通知；资产按方案打包，带清单、哈希和签名，按 dev、test、prod 部署；用户纠正的结论经审核写回租户语义包，相关 Agent 下次运行即生效。P5 的评测只是 Studio 里的一个类，P8 需要把它变成可单独使用、可在命令行运行的评测引擎。

## 决策

### 评测引擎独立成模块

评测放在新模块 `backend/eab-eval`，只依赖运行时和组装器：`Assertions` 负责逐条核对断言和裁判，`Scenarios` 把评测集里的 Given/When/Then 文本解析成普通用例，`SuiteRunner` 展开重复的场景并按最低通过率判定。怎样运行一个用例（以哪个用户、运行哪个版本、确认点怎么处理）由调用方提供，所以 Studio 的私有环境评测、治理中心的评测、升级回归和命令行冒烟共用同一套断言。Studio 原有的 `EvalRunner` 保留接口，改为委托评测引擎。

评测集 schema 只新增可选字段 `scenarios`：一段中英文都可用的 Gherkin 风格文本，支持“重复 N 次”。大模型输出不完全稳定，场景可以多跑几次，评测集按通过率而不是全部通过来判定。cases 与 scenarios 至少要有一个。

`pnpm eval:smoke` 在进程内启动平台与 DemoERP，运行全部冒烟评测集，默认 3 分钟预算，断网可用。

### 升级回归

演示中的标品升级是一份预置的新版本定义（`upgrades/transaction-anomaly-analyst-1.3.0.yaml`：改指令、加工具、把输出字段 severity 改名为 riskLevel）。升级时平台先找出所有扩展了该 Agent 的租户扩展，用扩展所在租户的评测集跑一次基线，再以厂商身份发布新版本，重新组装扩展并记录组装问题（字段改名会让钩子条件失效，报 HOOK_CONDITION_INVALID），然后再跑一次评测。基线通过而升级后失败的用例记为回归，结果写入 `upgrade_regressions`，并通知租户管理员和扩展负责人。

### 方案包

方案包从一个租户资产（通常是扩展）出发，沿引用收集本租户的资产，先写成一个 Solution 资产，再编译成包：清单列出包含的资产和内容哈希、依赖的标品资产、用到的连接别名；清单的规范化 JSON 计算哈希，平台用签名密钥签 `eab.dev/v1|solution|<方案>@<版本>|<哈希>`。部署时重新校验签名和哈希，被改过的包拒绝部署；test 和 prod 要求上一环境当前部署的就是这个包。方案包只引用连接别名，地址和凭据仍在各环境的绑定里。

### 经验回流写入租户语义包扩展

用户在结果卡片上点“结论有误”并说明理由，平台以内部身份 `platform/feedback` 经模型网关生成候选规则（规则说明、检查工具与 CEL 条件），校验条件语法和工具名，不合格时按原文生成没有检查条件的规则。租户管理员审核通过后，规则写入 `tenant.<租户>.semantic/<基础包>-ext`：这是一个租户层的语义包，用 `extends` 指向标品语义包，规则编号用租户前缀（T001-R-001）。

组装时，Agent 挂载的语义包如果被租户层的语义包扩展，扩展包会一起挂上；约束守卫对扩展包里带检查条件的规则一律生效，不需要改 Agent 本身，所以标品 Agent 下次运行就按新规则判断。追踪的守卫 span 记下规则来源（`eab.constraint.source`），能看出规则来自租户语义包。

### 指标

技术指标从运行记录和追踪补算，写入 `run_metrics`；流程指标和业务结果写入 `business_metrics`。演示用的 30 天历史由 `HistorySimulator` 按固定种子生成，标记为模拟数据，重新生成时替换。工具正确率取最近一次评测的通过率。

### 权限

治理中心接口只对租户管理员（全部）、租户开发者（只读）和平台运维（带 `?tenant=`）开放，厂商身份一律 403。写操作只允许租户管理员和平台运维，演示动作（模拟升级、生成历史、集成账号对照）只在演示模式下开放。版本差异按查看者裁剪后再比较，租户视角下标品指令只显示“已变更”，不给出前后内容和摘要。

### 集成账号对照

故事 D 的对照用平台签发的集成客户端令牌（`client:t001-integration`）直接调用 DemoERP 的 Open API，演示没有身份透传时会拿到全部采购组织的数据。这是演示专用的接口，写审计，运行时的 BO 调用仍只能走令牌交换，不存在降级到集成账号的路径。

## 后果

评测、回归、准入共用一套断言，评测集写法统一。租户的规则修正不需要复制或扩展标品 Agent，但租户语义包扩展只对挂载了对应基础包的 Agent 生效。升级回归目前只覆盖预置的升级，厂商发布任意新版本时自动回归需要在发布流程里接入同一个服务。Flyway 迁移 V7 与 P6、P7 的迁移编号相邻，合并时按 P7、P6、P8 的顺序，或打开 outOfOrder。
