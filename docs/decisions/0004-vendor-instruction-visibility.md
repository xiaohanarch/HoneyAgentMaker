# ADR 0004 标品指令的可见性与“复制为租户 Agent”

状态：已采纳（P1，2026-10-15）。“复制为租户 Agent”的界面在 P6 实现。

## 背景

主提示词 5.2 节要求租户看不到标品 Agent 的指令原文、提示词和内部评测集，范围覆盖追踪、有效定义预览和版本差异。5.3 节同时提供“复制为租户 Agent”操作：租户要改标品核心时，生成一份归租户所有、不再随标品升级的副本。复制时指令原文怎么处理，主提示词留给实现方决定，第 20 节的默认决策是：每个标品 Agent 准备一份公开版指令，复制时带上公开版。

## 决策

### 可见性

- 对租户隐藏的内容是标品 Agent 的 `instructions`、`additionalContext`、自由文本形式的 `constraints`、平台规则的 `instruction`，以及 `visibility: internal` 的评测集。
- 引用语义包规则编号的约束（如 `PUR-R-007`）对租户可见，组装后显示为规则的处置建议。语义包本身对租户可见，租户建 Agent 时要用到它。
- 裁剪只在输出边界做。注册中心按查看者返回 `redactAsset` 的结果；组装器始终产出完整的有效定义，交给运行时；对外接口只返回 `viewEffectiveDefinition` 的结果。
- 被隐藏的字段统一替换为占位对象 `{ $redacted: true, label, digest }`。`digest` 只用于在版本差异里显示“已变更”。服务端用 HMAC-SHA256 计算，密钥由平台私钥派生，截断到 64 位；不带密钥的摘要可以被字典比对猜出短文本，所以只在单元测试里使用。
- 有效定义里每个指令片段带 `confidential` 标记，由组装器在生成片段时决定，裁剪逻辑只看这个标记，不靠字段名猜测。只有标品层和平台层的片段标记为保密，租户自己的 Agent（例如复制出来的副本）对本租户可见。
- 租户看不到其他层的草稿版本。组装时解析资产也按查看者限定范围：以租户身份组装只能读到平台层、已发布的标品层和本租户的资产，读不到其他租户的资产，也读不到厂商的草稿。
- 资产写入时检查引用范围：租户资产只能引用平台层、标品层和本租户的资产，标品资产不能引用租户资产，越界的引用直接拒绝，不进入解析。
- 注册中心同时保存作者提交的 YAML 原文 `contentYaml` 和规范化 JSON。YAML 原文不经过裁剪，只能给本层身份看；P8 的版本差异视图必须基于规范化 JSON 经 `redactAsset` 裁剪后计算，不能直接比较 YAML 原文。

### 复制为租户 Agent

- 标品 Agent 增加 `spec.publicInstructions` 字段，写一份可以公开的指令概要，四个标品 Agent 都已提供。
- 复制时，副本的 `instructions` 取公开版指令，其余租户可见的字段（工具、语义包、扩展点之外的配置）原样复制；副本放在租户命名空间，界面提示“复制后不再随标品升级”。

## 生产环境的可选方案

1. 只提供公开版指令（本演示的做法）。实现简单，但标品方要维护两份指令。
2. 副本里保留一个“标品指令引用”的占位，运行时由平台注入当时版本的标品指令原文。租户既看不到原文又能复用标品能力，但副本会随标品升级而变化，和“复制后不再随标品升级”有矛盾，需要锁定版本。
3. 不提供复制，只允许扩展。最安全，但租户改不了核心逻辑时只能从零新建。

推荐生产环境用方案 1，配合扩展点覆盖大多数定制需求；方案 2 适合标品方愿意授权指令复用、但不愿公开原文的场景。

## 影响

- 有一组测试专门断言：租户视角的有效定义、资产读取接口、组装接口的序列化结果里，找不到任何一段标品指令或平台规则原文。P3 的追踪、P8 的版本差异都必须复用 `confidential` 标记和占位对象，并补同样的断言。
- 标品指令仍然会发送给模型，模型可能在输出里复述。P3 的输出守卫会检测与标品指令原文雷同的片段，这一层是兜底，不能替代输出边界上的裁剪。
