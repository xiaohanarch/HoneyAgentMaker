# ADR 0010 Studio 的工作区、私有环境、环境晋级与约束守卫

状态：已采纳（P5，2026-10-16）。

## 背景

主提示词第 10 节要求 Studio 用 13 步向导从一句话意图新建 Agent，每一步有 AI 推荐，右侧实时显示 YAML；开发者先在私有环境里测试（选测试用户和连接绑定），通过后发布到共享环境，按 dev、test、prod 晋级，晋级前有静态检查和评测门禁。故事 A 还要求约束 PUR-R-007 在追踪里可见地触发。

注册中心的资产版本不可修改（ADR 0004、0007），而向导每改一步都会改动草稿；运行时只运行注册中心里已发布的资产。需要决定草稿放在哪里、怎么在不发布的情况下运行草稿、环境怎么表示，以及约束怎样从提示词里的一句话变成可以检查的东西。

## 决策

### 工作区草稿

草稿放在平台数据库的 `studio_drafts` 表里，以 YAML 为准，可以反复修改。向导每采纳一步，服务端在 YAML 解析出的树上只改这一步负责的字段（例如协作 Agent 只替换工具列表里的 agent 条目），再写回 YAML；YAML 编辑模式改的是同一份。schema 问题随草稿一起返回，有问题的草稿也能保存，方便开发者继续改。

### 私有环境：叠加运行草稿

测试运行和评测时，草稿以叠加的方式交给组装和运行时（`OverlayResolver`）：草稿遮住注册中心里同名资产的全部版本，按已发布对待，草稿引用的其他资产照常从注册中心解析。叠加只对这一次运行生效，不改变注册中心，也不影响其他用户。运行记录里保存叠加的草稿和发起测试的开发者，挂起后恢复时据此重建。

演示模式下，开发者可以选择“以哪个用户身份测试”：平台为所选的本租户用户签发用户令牌，运行按该用户的身份和数据权限执行，写一条 `studio.test-run` 审计。发起测试的开发者可以查看这次运行的追踪。非演示模式下不开放，生产环境里应当用测试账号或模拟身份服务代替。

### 发布与环境晋级

发布时草稿写入注册中心：Agent 和评测集先都写成草稿版本（两者互相引用），再依次发布签名。同一内容已经发布过时直接返回原版本，内容变化时自动升一个补丁版本。发布后部署到 dev。

每个租户有 dev、test、prod 三个环境，部署记录在 `deployments` 表里，晋级即在下一个环境新增一条记录，回滚恢复上一个不同的版本。晋级 test 要求该版本已在 dev；晋级 prod 还要求静态检查没有错误，以及同一内容的评测通过。

评测门禁按内容哈希匹配：哈希去掉版本号后计算，开发者在私有环境里对草稿跑通的评测，发布出的同内容版本也算通过，不必对慢的真实模型再跑一遍。

租户新建的岗位助手和 Agent 只有部署到 prod 才进入统一入口的能力目录，并按 prod 的版本运行；标品资产不受影响。演示重置时清空草稿、部署和评测记录，注册中心里的版本保留，没有部署就不会出现在统一入口。

### 向导推荐

每一步先用 BM25 在能力清单里检索候选，再以平台内部身份 `platform/studio` 经模型网关请模型在候选里挑选并给出理由。模型的输出只接受候选里存在的引用，标识要符合命名规则，不合格或模型不可用时退回检索推荐，所以任何意图都有推荐。脚本化模型下按 `demo/scripts/studio.yaml` 的剧本输出。评测集初稿不经过模型：从已选语义包的已验证任务里取与意图相关的几条，断言优先用不变量（调用了任务要求的工具），再加一条按期望结论的裁判断言。

裁判在脚本化模型下是确定性的：评分标准里出现的规则编号和引号里的要点都要在回复里出现。配置了真实模型时用 judge 档位的模型，调用失败判为不通过，不静默通过。

### 约束守卫

语义包规则新增可选的检查条件 `check`：某个工具返回后，用 CEL 表达式（变量 `output` 是工具的返回数据）判断规则是否触发。组装时检查条件的语法。Agent 的约束引用了带检查的规则时，运行时在工具返回后判断，触发时写一个守卫 span（“约束 · PUR-R-007 触发”），推送 `constraint` 事件，并把规则和处置建议写进交给模型的工具结果（`platformConstraints` 字段）。判断只依赖运行日志里记录的工具结果，重放时结果相同，每条规则在一次运行里只触发一次。

PUR-R-007 的检查是：`purchase_order_list` 的结果里有逾期超过 90 天的订单。

### 与故事 A 的偏差

故事 A 原文里，价格谈判助手还会调用外部的“供应商风险舆情 Agent”。远程 Agent 需要 A2A，在 P7 实现。P5 的向导会推荐它，但标注“P7 接入后可调用”，不写进草稿；P7 完成后故事 A 补上这一步。

## 后果

- 草稿可以随意修改和测试，注册中心只保存发布过的不可变版本，审计和签名不受影响。
- 叠加运行让“私有环境”不需要单独部署一套服务，代价是草稿只对发起测试的开发者可见，团队协作测试要先发布到 dev。
- 约束从提示词里的一句话变成了确定性检查，追踪里能看到触发的时间和依据；但检查条件依赖工具返回数据的形状，工具改了字段时检查要跟着改，组装时只能发现语法错误。
- 评测门禁按内容哈希匹配，改了任何内容都要重新评测。
- 连接属于环境配置，启动时随平台和标品资产一起入库（`assets/tenants/*/connections`）；租户的其他资产仍是演示完成态快照，按需加载。
