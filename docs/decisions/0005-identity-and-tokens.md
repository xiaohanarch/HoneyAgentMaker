# ADR 0005 身份与令牌设计

状态：已采纳（P2，2026-10-15）

## 背景

主提示词第 7 章要求：每个 Agent 有独立身份；代用户执行时，有效权限是用户权限与 Agent 声明范围的交集；令牌交换参照 RFC 8693，委托令牌同时带 `sub`（用户）和 `act`（Agent）；受托自主运行使用事先登记、可撤销的委托；机机集成只能调用 Open API；身份透传失败一律拒绝，不能退回到技术账号。调研摘要提到，SAP 在漏配参数时会“静默退化成技术用户”，这是需要主动防范的坑。

## 决策

### 令牌与受众

平台内置一个模拟身份服务（`apps/platform/src/identity`），用 jose 签发 EdDSA 令牌。签名密钥与资产签名密钥分开存放，公钥以 JWKS 发布在 `/identity/v1/jwks.json`。令牌按受众分为四种，各自只能用在一个地方：

| 种类 | 受众 | 主体 | 用途 |
|---|---|---|---|
| 用户令牌 | `eab-platform` | 用户 | 调用平台接口；令牌交换时作为 `subject_token` |
| Agent 令牌 | `eab-agent-runtime` | `agent:<namespace>/<name>` | 只由平台运行时持有，令牌交换时作为 `actor_token`；`scope` 是 Agent 有效定义里声明的 BO 操作 |
| 委托令牌 | `demo-erp-bo` | 用户（受托运行时是委托人），`act.sub` 是 Agent | 调用 BO API，有效期 5 分钟 |
| 集成令牌 | `demo-erp-open` | `client:<id>` | 只能调用 Open API |

Agent 令牌的 `scope` 由平台在签发时计算，数据来源是该 Agent 在本租户的有效定义：直接挂载的 bo-api 工具，加上所挂技能里调用 bo-api 工具来源的步骤。租户扩展新增的工具也会进入这个范围，标品没有声明、租户也没有扩展的操作不会出现。

### 有效权限

令牌交换时，委托令牌的 `scope` 取以下集合的交集：

- 用户的业务权限：用户角色允许的 BO 操作，来自演示目录 `@eab/demo-directory`；
- Agent 令牌的 `scope`；
- 受托运行时，委托登记的授权范围；
- 调用方本次申请的范围（可选，平台调用时只申请当前这一个操作）。

交集为空时不签发令牌。DemoERP 在鉴权点 4 再次独立检查用户的业务权限和令牌的 `scope`，不依赖平台检查过这一事实。

### 受托自主运行

受托运行没有在线的用户，`subject_token` 写作 `delegation:<委托编号>`。委托令牌的 `sub` 是委托人，另带 `delegation_id` 和 `mode: delegated`。

这里采用“委托人加 Agent”，没有采用 Agent 的独立技术身份。理由是：审计里能看清“谁授权了这次自主运行”；委托人离职或权限收缩时，委托自动失去效力。

撤销在两处生效：

- 新的令牌交换立即失败；
- DemoERP 对受托令牌向平台核实委托状态，缓存最多 5 秒。

受托运行不执行需要人确认的 L2 写操作（规则 TOOL-007），改为生成建议。

### 失败即拒绝

平台调用 BO API 只有一条代码路径：`callBoApi`，先做令牌交换，再带委托令牌调用。令牌交换失败、委托无效、没有配置连接时，都抛出 `DelegationError`，代码中不存在改用集成账号的分支，测试也断言这时不会发出 HTTP 请求。

DemoERP 一侧，不带 `act` 的令牌一律返回 401 `AGENT_IDENTITY_REQUIRED`，集成令牌和用户令牌直接调用 BO API 也是同样结果。

### 平台与 DemoERP 之间的内部调用

事件推送和委托核实使用一个共享的内部调用密钥。事件请求带 `x-eab-signature` 头，内容是请求体的 HMAC-SHA256；委托核实请求带 `x-eab-internal-token` 头。

这个密钥由 `pnpm demo` 每次启动时随机生成，通过环境变量传给两个服务，不落盘、不进仓库。缺少密钥时，受托调用会被拒绝，同样是失败即拒绝。

## 生产环境的做法

- **用户登录**：对接企业 IdP（OIDC），平台只做令牌交换和校验，不再签发用户令牌。“选人即登录”只存在于演示。
- **Agent 身份**：在身份目录里注册为工作负载身份（workload identity），令牌由运行时通过工作负载凭证换取，不长期持有。
- **内部调用**：改用 mTLS 或工作负载身份令牌，不用共享密钥。
- **委托**：纳入审批流程，并设置到期提醒；撤销通过事件推送通知下游，不依赖轮询和缓存。

## 影响

- P1 的 `x-eab-viewer` 请求头已经删除，平台接口一律从 Bearer 用户令牌推导查看者：租户用户对应租户身份，厂商研发对应厂商身份，平台运维对应平台身份。
- P3 的运行时、MCP 网关调用 BO 工具时必须经过 `callBoApi`，不能直接请求 DemoERP。
