# 亮点与优势

这份文档说明这个项目作为多租户 ERP Agent 平台参考原型的价值：哪些机制是真实实现、为什么这样设计、在演示的哪里可以看到。系统结构见 `docs/architecture.md`，操作路径见 `demo/DEMO.md` 与 `docs/usage.md`。

## 三层资产与标品指令保护

平台把资产分为平台层、厂商标品层、租户层。租户在标品之上做扩展：追加指令、加工具和技能、挂结果钩子、设人工确认点，扩展是租户自己的资产，标品升级时按组装规则合并（`backend/eab-assembler`）。租户视角永远看不到标品指令原文：有效定义预览里是占位块，追踪、版本差异同样不泄露。这解决了 ERP 厂商把 Agent 开放给租户定制时的核心顾虑，标品的知识产权与行为基线都留在厂商手里。演示位置是故事 B 的「有效定义」页。

## 身份透传与四处鉴权

用户身份从统一入口一直透传到业务 API，鉴权点有四处：入口（鉴权点 1）、Agent 交接前（2）、工具网关（3）、BO API 应用侧（4）。身份缺失或令牌交换失败一律拒绝，任何路径都不退回技术账号；需要无人值守的场景用事先登记、可撤销的委托。演示里最直观的对照是故事 D 的「集成账号对照」：同一问题走 BO API 按用户数据范围过滤（华东或华南），走 Open API 全量返回，两条路的差别一目了然。

## 硬约束写在代码里

写操作分级（L1 免确认、L2 人工确认、L3 禁止）、职责分离、金额阈值写在工具定义、策略守卫和 BO API 里，模型绕不过去；语义规则用工具名加 CEL 条件表达，在工具返回后由约束守卫判定，规则的适用性可以自动检查。安全边界因此从提示词里的软约束变成了系统里的硬约束。演示位置：故事 D 里审批自己提交的变更单被职责分离拒绝，故事 A 的测试链路里 PUR-R-007 约束触发。

## 挂起与恢复靠运行日志重放

会产生副作用或不确定结果的步骤（模型调用、工具调用、鉴权裁决）都按结构化路径记入运行日志（`Journal`），L2 确认点挂起后、进程中断后都能重放恢复。确认点、故障恢复、审计反查共用同一份事实来源。故事 D 的审计反查把「谁、通过哪个 Agent、哪次运行改了这张订单」一次查清，就是这份日志的直接应用。

## 升级回归保护租户扩展

厂商发布标品新版本时，平台自动用依赖该标品的租户扩展的评测集做回归：演示场景里新版本把输出字段改名，租户钩子的条件表达式失效，回归用例失败并通知租户管理员。租户先知情再决定，升级不会静默破坏租户的定制。这是故事 F 的核心一幕。

## 经验回流到语义包

业务用户对结论点「结论有误」，反馈进入治理中心成为候选规则，附判定条件；管理员审核通过后写入租户语义包，对本租户全部 Agent 立即生效，追踪里能看到规则来自哪个语义包。纠正一次，长期受益，企业的业务口径随使用沉淀。故事 F 的后半段。

## 评测驱动的生命周期

Agent 从一句话意图开始建模，评测集可以由模型生成初稿；发布前评测必须通过，dev、test、prod 逐级晋级，到 prod 的 Agent 才进统一入口。租户扩展发布即生效，但标品公开评测集和扩展评测集都要通过，评测时确认点一律拒绝，保证评测可以自动运行。治理中心有三层指标与 30 天趋势。演示位置：故事 A 的发布晋级、故事 B 的发布门禁。

## 低代码与专业代码是同一条链路

Studio 的可视化向导、`eab` CLI、Studio MCP Server 指向同一条草稿链路，push 不直接写注册中心；导出的代码工程与 init 模板同构，这是结构性保证。专业开发者可以在自己的 IDE 里用编码 Agent 协作开发扩展，成果回到同一条评审、评测、发布链路。见 `docs/pro-code.md` 的完整实录。

## 对等集成带身份

出站 A2A 调用每次携带最终用户的短期服务令牌，没有用户身份时拒绝；入站调用要求资产声明触发器，模拟外部平台的脚本先被拒绝、带上用户令牌后成功，全程审计。外部 Agent 样例（Python/LangGraph、TypeScript）和物流 MCP Server 真实可跑，与原生 Agent 共用一个入口参与路由。演示位置是故事 C。

## 可演示、可复现、可验证

脚本化模型让演示断网可跑、测试结果确定可复现；`DemoScriptsTest` 检查剧本可加载、示例话术有剧本，保证脚本化与真实模型的行为对齐。种子数据用黄金样本锁定，六个故事各有 Playwright 端到端测试，每个开发阶段有验收脚本，主线机制有走查脚本在两秒内过一遍。主提示词第 18 节的八条验收标准逐条有证据，见 `docs/acceptance.md`。

## 边界

这是一个概念演示：存储用 SQLite，业务系统是模拟的 DemoERP，单机部署，模型网关对接脚本化、Anthropic、OpenAI 兼容三种提供方。生产化需要在多租户数据隔离、高可用、密钥管理、真实 ERP 适配器等方向补齐。机制层面（资产组装、鉴权与委托、策略守卫、运行日志、升级回归、经验回流、评测门禁、代码通道）都是真实实现，可以直接对照代码评估，适合作为自建平台时的机制参考与选型依据。
