# 分阶段提示词

主提示词描述"要什么"，本文描述"按什么顺序做"。共 11 个阶段，每个阶段一段可以直接粘贴给 Claude Code 的提示词。建议每个阶段开一个新会话（或者在阶段之间执行一次 `/compact`），会话开头让它先读 `CLAUDE.md` 和主提示词的相关章节。

阶段顺序的考虑：先把资产模型、身份鉴权、模拟 ERP 这些"地基"打牢，再做运行时和统一入口，然后才做 Studio 界面。这样每个阶段都能独立演示，界面做到一半也有东西可以给人看。

| 阶段 | 内容 | 完成后能演示什么 |
|---|---|---|
| P0 | 工程骨架 | 空壳服务跑起来 |
| P1 | 资产模型、注册中心、组装器 | 命令行里看到标品加租户扩展的组装结果 |
| P2 | DemoERP、身份服务、四处鉴权 | 用不同用户调 BO API，看到数据权限过滤；Open API 对照 |
| P3 | 模型网关、工具网关、Agent 运行时、追踪 | 命令行里跑通一个标品 Agent，导出追踪 |
| P4 | 统一入口与路由 | 在浏览器里和采购助手对话，看到路由面板和追踪 |
| P5 | Studio 第一部分：从意图新建 Agent、测试、发布 | 故事 A |
| P6 | Studio 第二部分：扩展标品 Agent、工具中心、技能编辑器 | 故事 B |
| P7 | A2A 双向互通与外部 Agent 样例 | 故事 C |
| P8 | 治理中心、评测、生命周期、升级回归、经验回流 | 故事 D、F |
| P9 | 意图驱动生成与需求闭环、专业代码通道 | 故事 E；Claude Code 通过 Studio MCP 开发扩展 |
| P10 | 架构视图、演示控制台、打磨与端到端测试 | 完整 15 分钟演示 |

---

## P0 工程骨架

```
阅读 CLAUDE.md 和 docs/brief/02-主提示词.md 第 4、14、15、20 节。

目标：搭好单仓工程骨架，后续阶段只往里填内容。

任务：
1. 按主提示词第 15 节建立 pnpm workspace 目录结构，TypeScript strict，ESLint、Prettier、Vitest、Playwright 配好。
2. 后端框架在 Fastify 和 Hono 之间选一个，写 ADR（docs/decisions/0001-backend-framework.md）。
3. 查阅 A2A 和 MCP 的官方最新文档与 SDK，确定版本，写 ADR（0002-protocol-versions.md），说明 Agent Card 路径兼容策略。
4. 建 apps/platform、apps/demo-erp、apps/studio-web（含统一入口路由）的最小可运行服务，各有 /health。
5. 前端用 React + Vite + Tailwind + shadcn/ui，做好布局框架：顶部切换"统一入口 / Studio / 治理中心"，身份切换下拉框（先写死几个演示用户）。按主提示词第 16 节定好三类资产来源的颜色和图标规范，写进 packages/ui。
6. pnpm demo 用一个脚本并行启动所有服务；提供 docker-compose.yml。
7. README 写明项目定位、与 SAP 无关的声明、启动方式。
8. 更新 CLAUDE.md 的常用命令。

验收：pnpm install && pnpm demo 后三个服务健康检查通过，浏览器能打开前端框架；pnpm test、pnpm lint 通过。
```

## P1 资产模型、注册中心、组装器

```
阅读主提示词第 3、5 节。

目标：实现声明式资产体系，这是整个平台的核心。

任务：
1. packages/spec：用 zod 定义所有 kind 的 schema（Assistant、Agent、Skill、ToolSource、SemanticPack、KnowledgeSource、AgentExtension、RemoteAgent、Workflow、EvalSuite、DevRequest、Solution、Connection），导出 JSON Schema。YAML 解析、校验、错误信息要对人友好（中文，指明行号和字段）。
2. 资产注册中心（apps/platform 内的模块）：存储、版本、状态、命名空间、按层的可见性规则（主提示词 5.2）。租户对 vendor.* 的写请求在 API 层拒绝并写审计。
3. 标品包签名：发布时对内容做哈希并用平台私钥签名，加载时校验。
4. packages/assembler：按主提示词 5.4 的七条规则实现组装，输出"有效定义"，每段带来源标记。提供按查看者身份脱敏的视图（租户看不到标品指令原文）。单元测试覆盖：追加指令顺序、工具并集与冲突、确认策略取最严、钩子顺序与失败隔离、模型范围限制、版本范围解析、脱敏。
5. 在 assets/vendor 下写好主提示词 13.1 的标品资产初版（Agent 指令可以先简短，后续阶段打磨），以及三个语义包。语义包严格按 5.5 的结构，包含投影段引用、增量段、原生段。
6. 静态检查（主提示词 10.8.1）的规则引擎先实现核心几条，后续阶段补全。
7. 一个开发用命令：pnpm assets:assemble <agent> --tenant t001 --as tenant|vendor，打印组装结果，用于自测。

验收：所有标品资产校验通过；组装器测试全部通过；命令行能打印"交易异常解析 Agent + t001 扩展"的有效定义，租户视角下标品指令为占位块。
```

## P2 DemoERP、身份服务、四处鉴权

```
阅读主提示词第 6、7 节。

目标：模拟 ERP 和身份体系，演示"Agent 不越权"的地基。

任务：
1. apps/demo-erp：SQLite + Drizzle，按 6.1 建模采购、库存、财务三个域；两个租户；按 6.2 生成有故事性的种子数据（百润精密有逾期 120 天的订单 PO-2026-0117；华东、华南供应商数量明显不同）。种子脚本可重复执行。
2. BO API 与 Open API 两套接口（6.3）。BO API 满足主提示词列出的全部规范：业务含义描述、结构化错误、幂等键、数据权限过滤说明、路径版本。输出 OpenAPI 文档，写操作级别用 OpenAPI 扩展字段声明（例如 x-write-level）。
3. 元数据服务（/meta/v1）与业务事件（先用平台内的事件总线，DemoERP 通过 webhook 推送）。
4. DemoERP 提供几张极简的只读页面（供应商详情、采购订单详情），供导航型交互跳转。
5. 平台内的模拟身份服务（jose）：用户登录（选人即登录）、客户端凭证、令牌交换（sub=用户，act=Agent）、委托登记与撤销。
6. packages/policy：鉴权点 1 至 3 的策略引擎（JSON 规则），每次裁决产出结构化记录；写操作分级与 SoD 检查；DemoERP 实现鉴权点 4。
7. 失败即拒绝：令牌交换失败、委托缺失时一律拒绝，写测试证明不会退回技术账号；平台禁止 Agent 使用客户端凭证调用 BO API。
8. 审计存储与查询 API（7.5）。

验收：用张敏、李强的委托令牌调同一个 BO API 接口，返回不同且带过滤说明；用集成账号调 Open API 返回全部；SoD 场景被拒；撤销委托后受托调用被拒；所有裁决可在审计 API 中查到。单元测试覆盖策略引擎与令牌交换。
```

