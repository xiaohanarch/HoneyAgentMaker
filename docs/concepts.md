# 术语

本文解释系统里用到的术语，P0 到 P10 涉及的术语都已收录。术语的完整定义以 `docs/brief/02-主提示词.md` 第 3 节为准。

## 总体结构

五层两翼是平台的总体结构（主提示词 4.1 节）：中间五层从上到下是用户体验（统一入口、IM 渠道、外部调用方）、Agent 编排（路由、岗位助手、工作流、人工确认）、应用（ERP、标品 Agent、租户 Agent、远程 Agent）、知识（语义包、文档、元数据）、平台能力（模型网关、工具网关、Agent 网关、运行时、记忆）；左翼安全与治理、右翼运营与运维贯穿五层；开发态贯穿带串起 Studio、CLI 和 Studio MCP Server。前端「架构视图」页按这个结构画图，支持选一次运行回放，组件随 span 依次点亮。

## 资产与分层

资产是平台的核心数据，全部用 YAML 声明，信封结构统一为 `apiVersion: eab.dev/v1`、`kind`、`metadata`、`spec`。界面和文件是同一份数据的两种视图。schema 只在后端的 `eab-spec` 模块定义一份，平台和命令行共用，仓库根目录的 `schemas/` 下有导出的 JSON Schema，可供编辑器做校验和补全。

资产分三层，由命名空间决定。`platform` 是平台层，放平台安全规则；`vendor.<域>` 是厂商标品层，放随产品交付的 Agent、技能、语义包；`tenant.<租户编号>.<分组>` 是租户层，只有本租户可见。只有本层身份能写本层命名空间，租户对标品层的任何写请求在接口层直接拒绝并写审计。

资产引用写作 `命名空间/名称[@版本范围]`，例如 `vendor.fin/transaction-anomaly-analyst@^1.0`。版本范围用 semver 语法，解析时取满足范围的最高已发布版本。方案（Solution）里的引用必须锁定到具体版本。

资产的每个版本不可修改，改动必须使用新的版本号。版本有四种状态：草稿、测试中、已发布、已下线。标品层和平台层的资产发布时签名（Ed25519 签名内容哈希），每次读出交给组装器之前验签，签名不符拒绝加载。

## 资产种类

| kind | 含义 |

| Workflow | 工作流，供钩子和技能复用 |

| SemanticPack | 语义包，分投影段、增量段、原生段 |
| KnowledgeSource | 文档知识库，作为文档检索工具挂到 Agent 上 |
| AgentExtension | 租户对标品 Agent 的扩展 |
| RemoteAgent | 通过 A2A 接入的外部 Agent |
| EvalSuite | 评测集，分公开与内部、冒烟与完整 |

## 扩展与组装

扩展点是标品 Agent 声明的、允许租户叠加内容的位置，共七类：`instructions.append`、`tools.add`、`skills.add`、`knowledge.add`、`hooks`、`approvals.add`、`model.select`。扩展只能使用目标 Agent 声明过的扩展点。

组装是运行时把平台规则、标品 Agent、语义包和租户扩展合成一份有效定义的过程，由 `eab-assembler` 模块实现。指令按固定顺序拼接成片段，每个片段记录来源层、来源资产和字段；工具取并集，租户工具重名时拒绝发布；人工确认策略取最严；钩子先标品后租户，租户钩子失败不影响主流程；模型档位只能在标品允许的范围内选择；扩展的目标版本范围解析到满足范围的最高已发布版本。

有效定义按查看者裁剪后才对外输出。租户视角下，标品指令和平台规则原文显示为占位块，只保留来源和规则名。

## 条件表达式

钩子、确认点、工作流分支里的条件用 CEL 编写（ADR 0003），组装时按 Agent 声明的输出结构做类型检查。

## 静态检查

发布前运行的检查规则（主提示词 10.8.1 节），目前实现四条：资产里不得出现硬编码地址和凭据；工具必须声明写操作级别，付款、过账类最高 L2；扩展只能用目标 Agent 声明过的扩展点；引用的资产、语义包规则必须存在且版本兼容。

## 身份与鉴权

双重身份是指，Agent 代用户执行时同时带着用户和 Agent 两个身份。有效权限是用户的业务权限、Agent 声明的操作，以及受托运行时委托的授权范围，三者取交集。

平台通过令牌交换（RFC 8693）签出委托令牌。令牌里的 `sub` 是用户，`act.sub` 是 Agent，只有 BO API 接受这种令牌。

调用模式有三种：

- 代用户操作：用户在线发起；
- 受托自主运行：由事件或定时任务触发，使用事先登记、可以撤销的委托；
- 机机集成：使用集成账号，没有人的身份，只能调用 Open API。

一次请求要经过四处鉴权：入口、Agent 交接、工具与 MCP 网关、BO API。前三处由平台的策略引擎负责，第四处由 DemoERP 负责。

写操作分四级：L0 只读；L1 出建议；L2 写入前必须由人确认；L3 可以自主执行，但需要租户管理员显式开启。付款、过账类工具最高只能到 L2。

职责分离（SoD）要求同一个用户不能既提交又审批同一张单据，平台的策略引擎和 DemoERP 各检查一次。

BO API 与 Open API 的区别：BO API 是 Agent 调用业务数据的标准通道，接受委托令牌（用户加 Agent 双重身份），按用户的数据范围过滤；Open API 是系统集成通道，用集成账号调用，只做租户隔离，不按用户过滤。平台规定 Agent 一律走 BO API，两条通道同一问题的对照可以在治理中心和演示控制台查看。

身份透传失败即拒绝：令牌交换失败、委托失效、连接配置缺失时，一律拒绝调用，绝不退回到集成账号或其他技术身份。

## 运行时

有效定义交给运行时后，一次运行就是“模型调用、工具调用”的循环。运行时由三类执行器组成：技能执行器（确定性步骤，不调用模型）、声明式 Agent 执行器（YAML 定义的 Agent），以及代码 Agent 执行器（P7 通过 A2A 接入）。

工具网关是 Agent 使用工具的唯一通道，每次调用都先经过鉴权点 3 和监督层守卫，再按工具类型执行。

模型处理管道是模型调用前后的固定环节：知识检索注入、提示模板、敏感数据脱敏与还原、输入输出内容过滤。

脚本化模型是默认的模型提供方，按演示剧本给出确定性的工具调用和回复，回复基于真实的工具结果渲染。剧本没有覆盖的话术回退到规则回复。

运行日志按结构化路径记录模型调用、工具调用和确认决定。运行等待人工确认时挂起，用户决定后按日志重放，已经发生的步骤不会重复执行。

监督层是提示词之外的确定性检查：写操作前的守卫、输出引用核对（找不到依据的单号和金额标注“未经核实”）、行为异常告警。

长期记忆按“租户、用户、Agent”三元组隔离，保存用户偏好和确认过的事实。

## 统一入口

能力目录是本租户可见的岗位助手、Agent 和导航场景的清单，每个条目带路由说明和示例话术，是路由召回的对象。

场景（routing examples）是 Agent 或导航能力声明的一段场景描述和几条示例话术，路由按它与用户提问的相似度召回打分；两个能力的场景相近、置信度不足时触发澄清。

两级编排指入口先选岗位助手，岗位助手再在成员 Agent 里选。每一级都是候选召回、权限过滤、决策三步。

澄清是路由置信度不够时请用户在两个候选里选一个；能力缺口是没有合适的、对用户开放的能力，用户可以把原话提交为扩展需求（DevRequest），交给开发者评估。

受托运行由业务事件触发，以登记过的委托运行，结果推送到委托人的通知区。

## Studio

工作区草稿是向导里正在编辑的资产，可以反复修改，发布时才写入注册中心成为不可修改的版本。

私有环境是开发者测试草稿的地方：草稿叠加在已发布资产之上运行，只对发起测试的开发者生效，可以选择以哪个用户的身份测试。

环境晋级指已发布的版本依次部署到 dev、test、prod。晋级 prod 前要过门禁：静态检查没有错误，同一内容的评测通过。租户的 Agent 部署到 prod 后才对最终用户可见。

约束守卫按语义规则的检查条件，在工具返回后判断约束是否触发。触发时在追踪里留下守卫 span，并要求模型先说明约束和处置建议。

确定性裁判是脚本化模型下评测用的裁判：评分标准里的规则编号和引号里的要点都在回复里出现才算通过。

## 扩展、工具中心与技能（P6）

扩展是租户在标品 Agent 声明的扩展点上做的增量修改：追加指令和约束、增加工具、技能、知识、在指定事件上挂工作流或技能、增加确认点、在允许的档位里选模型。扩展不能删除或覆盖标品的内容，发布前要同时通过标品的公开评测集和扩展自己的评测集，发布后立即对本租户生效。

有效定义预览展示扩展叠加到标品之后的样子。标品指令在租户视角下是锁住的占位块，租户追加的片段标出来源。

复制为租户 Agent 是扩展之外的另一条路：生成一份归本租户所有的 Agent，指令取标品的公开版指令，之后不再随标品升级。

MCP 审批指租户登记的 MCP Server 要经租户管理员批准，才能用在生产环境。Agent 晋级 prod 和扩展发布时检查。

技能单独测试指不建 Agent、以测试用户的身份直接执行技能，查看每一步的输入、输出和状态。

## A2A 与外部 Agent

远程 Agent 是运行在平台之外、经 A2A 协议接入的 Agent，在平台里登记为 RemoteAgent 资产。它可以挂到岗位助手下，也可以被平台里的 Agent 当作工具调用，执行动作类型叫 agent-request。

Agent 卡片（Agent Card）是 A2A 协议里 Agent 的自描述文件，声明名称、描述、技能、交互模式和认证方式。平台接入外部 Agent 时读取它做连通性测试；平台对外暴露的岗位助手和 Agent 也按 A2A 规范提供卡片。

服务令牌是平台调用外部 Agent 时签发的短时令牌，主体是最终用户，act 是发起调用的平台 Agent。外部 Agent 凭它知道“谁在替谁问”，平台凭它保证身份不会丢失；签发不了就不调用。

多轮续接指外部 Agent 返回 input-required 时，平台记住对方的 contextId 和 taskId，用户在同一会话里的回答直接交回同一个外部 Agent。

超时转异步指外部 Agent 60 秒内没有给出结果时，平台先回复“已转为异步任务”，对方处理完后推送回调，结果出现在通知区。

入站 A2A 是外部平台的 Agent 调用平台里的岗位助手或 Agent。它们的触发器里要声明“被其他 Agent 调用”，调用方必须带用户令牌，和最终用户在统一入口提问一样经过四处鉴权，并在审计里留下调用方。

代码 Agent 是用 Java 代码写的 Agent，用代码 Agent SDK 以 A2A 对外服务，再登记为远程 Agent。

## 治理与演进

血缘指资产之间的引用关系：助手包含哪些 Agent，扩展基于哪个标品 Agent，Agent 委派哪些远程 Agent。

上架准入是租户资产进入 prod 前的检查：评测通过、工具写级别合规、用到的 MCP Server 已审批、内容完整。

升级回归是标品发布新版本时，用依赖它的租户扩展的评测集在升级前后各跑一次，找出升级后才失败的用例。

方案包是一组租户资产编译成的部署单元，带清单、内容哈希和平台签名，按 dev、test、prod 依次部署。

经验回流指用户纠正的结论经管理员审核，变成租户语义包扩展里的一条规则，挂载对应基础语义包的 Agent 下次运行即按新规则判断。

场景式评测是用 Given/When/Then 写的对话测试，可以重复运行，按通过率判定，适合输出不完全稳定的大模型。

## 演示

完成态快照是 `assets/tenants/t001` 里预置的一组租户资产（扩展、技能、评测集、语义包扩展），平时启动不加载；跳到故事 F 起点或一键生成完成态时发布它们，让升级回归和经验回流有现成的对象。

演示控制台是右上角的滑杆图标，提供重置数据、跳到各故事起点、触发业务事件、模拟标品升级、切换演示身份和集成账号对照。演示状态操作只对租户管理员开放，演示模式未开启时相关端点一律 404。15 分钟演示的操作脚本见 `demo/DEMO.md`。
