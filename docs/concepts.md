# 术语

本文解释系统里用到的术语，随阶段推进补全。术语的完整定义以 `docs/brief/02-主提示词.md` 第 3 节为准。

## 资产与分层

资产是平台的核心数据，全部用 YAML 声明，信封结构统一为 `apiVersion: eab.dev/v1`、`kind`、`metadata`、`spec`。界面和文件是同一份数据的两种视图。schema 只在后端的 `eab-spec` 模块定义一份，平台和命令行共用，仓库根目录的 `schemas/` 下有导出的 JSON Schema，可供编辑器做校验和补全。

资产分三层，由命名空间决定。`platform` 是平台层，放平台安全规则；`vendor.<域>` 是厂商标品层，放随产品交付的 Agent、技能、语义包；`tenant.<租户编号>.<分组>` 是租户层，只有本租户可见。只有本层身份能写本层命名空间，租户对标品层的任何写请求在接口层直接拒绝并写审计。

资产引用写作 `命名空间/名称[@版本范围]`，例如 `vendor.fin/transaction-anomaly-analyst@^1.0`。版本范围用 semver 语法，解析时取满足范围的最高已发布版本。方案（Solution）里的引用必须锁定到具体版本。

资产的每个版本不可修改，改动必须使用新的版本号。版本有四种状态：草稿、测试中、已发布、已下线。标品层和平台层的资产发布时签名（Ed25519 签名内容哈希），每次读出交给组装器之前验签，签名不符拒绝加载。

## 资产种类

| kind | 含义 |
|---|---|
| Assistant | 岗位助手，编排一组 Agent，带 KPI |
| Agent | 由大模型驱动的执行单元，字段名与 Joule Studio 编辑器对齐 |
| Skill | 确定性的步骤流程，不依赖大模型推理 |
| Workflow | 工作流，供钩子和技能复用 |
| ToolSource | 工具来源：BO API、MCP Server 或 HTTP，只写连接别名，每个工具声明写操作级别 |
| SemanticPack | 语义包，分投影段、增量段、原生段 |
| KnowledgeSource | 文档知识库，作为文档检索工具挂到 Agent 上 |
| AgentExtension | 租户对标品 Agent 的扩展 |
| RemoteAgent | 通过 A2A 接入的外部 Agent |
| EvalSuite | 评测集，分公开与内部、冒烟与完整 |
| DevRequest | 业务用户提交的开发需求 |
| Solution | 方案，部署单元 |
| Connection | 连接别名及其按环境的绑定，是唯一允许出现地址的资产 |
| PlatformRuleSet | 平台安全规则，只能放在 platform 命名空间 |

## 扩展与组装

扩展点是标品 Agent 声明的、允许租户叠加内容的位置，共七类：`instructions.append`、`tools.add`、`skills.add`、`knowledge.add`、`hooks`、`approvals.add`、`model.select`。扩展只能使用目标 Agent 声明过的扩展点。

组装是运行时把平台规则、标品 Agent、语义包和租户扩展合成一份有效定义的过程，由 `eab-assembler` 模块实现。指令按固定顺序拼接成片段，每个片段记录来源层、来源资产和字段；工具取并集，租户工具重名时拒绝发布；人工确认策略取最严；钩子先标品后租户，租户钩子失败不影响主流程；模型档位只能在标品允许的范围内选择；扩展的目标版本范围解析到满足范围的最高已发布版本。

有效定义按查看者裁剪后才对外输出。租户视角下，标品指令和平台规则原文显示为占位块，只保留来源和规则名。

## 条件表达式

钩子、确认点、工作流分支里的条件用 CEL 编写（ADR 0003），组装时按 Agent 声明的输出结构做类型检查。

## 静态检查

发布前运行的检查规则（主提示词 10.8.1 节），目前实现四条：资产里不得出现硬编码地址和凭据；工具必须声明写操作级别，付款、过账类最高 L2；扩展只能用目标 Agent 声明过的扩展点；引用的资产、语义包规则必须存在且版本兼容。

## 身份与鉴权

双重身份是指，Agent 代用户执行时同时带着用户和 Agent 两个身份。有效权限是用户的业务权限、Agent 声明的操作，以及受托运行时委托的授权范围，三者取交集。

平台通过令牌交换（RFC 8693）签出委托令牌。令牌里的 `sub` 是用户，`act.sub` 是 Agent，只有 BO API 接受这种令牌。

调用模式有三种：

- 代用户操作：用户在线发起；
- 受托自主运行：由事件或定时任务触发，使用事先登记、可以撤销的委托；
- 机机集成：使用集成账号，没有人的身份，只能调用 Open API。

一次请求要经过四处鉴权：入口、Agent 交接、工具与 MCP 网关、BO API。前三处由平台的策略引擎负责，第四处由 DemoERP 负责。

写操作分四级：L0 只读；L1 出建议；L2 写入前必须由人确认；L3 可以自主执行，但需要租户管理员显式开启。付款、过账类工具最高只能到 L2。

职责分离（SoD）要求同一个用户不能既提交又审批同一张单据，平台的策略引擎和 DemoERP 各检查一次。

身份透传失败即拒绝：令牌交换失败、委托失效、连接配置缺失时，一律拒绝调用，绝不退回到集成账号或其他技术身份。
